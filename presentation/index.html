The problem · 02 / 10

One developer.
Several accounts to remember.

Wrong commit email

A client commit inherits a personal identity from global Git settings.

Unexpected sign-in

Moving to another repository triggers a credential prompt or access error.

Unclear permissions

A failed push leaves you guessing whether the account, token or repository policy is responsible.

The solution · 03 / 10

Assign the account once.
Apply it to the project.

Save your profiles, map each repository to its intended account, and apply the local Git identity and authentication setup.

Example

Personal portfolio → personal account
Client application → client account
Company platform → work account

Commit author and push authentication are different. The extension helps you configure both.

Install · 04 / 10

Start with the VS Code extension.

  1. Download v1.6.2

    Get the VSIX from the product website’s Releases section.

  2. Install from VSIX

    VS Code → Extensions → … → Install from VSIX. Select the file and reload.

  3. Open your project

    Use a local GitHub repository. Windows HTTPS setup requires Git Credential Manager.

  4. Open the dashboard

    Ctrl + Shift + P → GitHub: Open Control Panel Dashboard.

Requires VS Code 1.75+. The optional desktop companion runs from source and needs VS Code open.

First setup · 05 / 10

Add. Assign. Apply. Check.

  • Add a profile with browser login or a personal access token.
  • Assign your project folder to the intended account.
  • Apply the profile using Use for This Project.
  • Check Health for the saved account and repository.

Repeat for your other account in a separate project window. Your existing commit and push tools stay part of the workflow.

Everyday use · 06 / 10

Know what to do
when access changes.

New project

Create a mapping and apply the chosen profile before working.

Expired login

Use Reauthenticate for a browser profile, or Save / Update Token. Reapply the profile and check Health.

Push rejected

Check the account, token and project mapping. Branch protection, SSO and workflow permissions can still prevent a push.

AI access · 07 / 10

You choose which project
AI tools may read.

  • Find the AI Agent Access card at the top of the dashboard.
  • Review the project and account; select Enable AI Access and confirm.
  • Connect a local MCP client to read repository metadata.
  • Select Disable AI Access to withdraw approval.
Read only means read only.

This connector does not commit, push or edit. Your token stays inside VS Code. Enabling approval alone does not configure an AI client.

Boundaries & roadmap · 09 / 10

A clear line between
available and planned.

Available now

Windows-first extension, local identity, saved accounts, health checks, shared desktop view and approved AI repository metadata.

Local Windows automated checks and one approved live-project read/push have succeeded. Full two-account verification remains open.

Next

Live account isolation and platform vault verification; pull-request reads; GitHub Actions visibility and controls; tested Windows/macOS/Linux installers.

No release dates promised. Enterprise Server, GitLab and Bitbucket are later ideas, not current features.

Your pilot · 10 / 10

Try two projects.
Keep the results simple.

  • Assign project A to account A and project B to account B.
  • Check Health, then use harmless test branches for your normal Git workflow.
  • Enable AI reads in A. Confirm B remains denied until separately approved.
  • Disable A. Confirm further AI reads fail while B keeps its own access.

Share pass/fail results and useful errors, never tokens or connection keys.
