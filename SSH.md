# SSH Strategy & Configuration Guide

## Overview

SSH is the preferred authentication mechanism for developers managing multiple GitHub accounts because OpenSSH provides native host aliasing and identity key isolation.

---

## SSH Key Architecture

Each account profile is associated with a unique SSH key pair:

- **Personal Account**: `~/.ssh/id_ed25519_personal`
- **Work Account**: `~/.ssh/id_ed25519_work`
- **Client Account**: `~/.ssh/id_ed25519_client`

---

## OpenSSH Configuration File (`~/.ssh/config`)

The tool automatically generates and maintains Host blocks inside `~/.ssh/config`:

```sshconfig
# Generated by GitHub Account Manager for profile: Personal
Host github.com-mohammed-personal
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_personal
    IdentitiesOnly yes

# Generated by GitHub Account Manager for profile: Work
Host github.com-mohammed-work
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_work
    IdentitiesOnly yes
```

### Key Directives Explained:
- `Host`: Unique alias used in repository remote URLs.
- `HostName`: Real destination server (`github.com`).
- `User`: Standard SSH user for GitHub (`git`).
- `IdentityFile`: Absolute path to private key file.
- `IdentitiesOnly yes`: Forces OpenSSH to ONLY present the key specified in `IdentityFile`, preventing key exhaustion errors (`Too many authentication failures`).

---

## Remote URL Rewriting

When a workspace opens:
1. Origin remote URL is checked (e.g. `git@github.com:company/backend.git`).
2. Remote is updated to use the host alias: `git@github.com-mohammed-work:company/backend.git`.
3. OpenSSH routes connection seamlessly using the correct key pair.
