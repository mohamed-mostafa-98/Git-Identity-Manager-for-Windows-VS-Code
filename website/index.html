The problem

Switching projects is easy.
Switching identities should be, too.

Your personal project works. A client repository asks you to sign in again. A work commit uses the wrong email. Managing several accounts becomes a trail of credential resets and settings to remember.

01 / IDENTITY

Stop guessing which account belongs here.

Save a folder or repository-owner assignment and apply that profile’s name and email to the local repository.

02 / AUTHENTICATION

Keep reusable credentials.

Browser login and saved tokens stay in VS Code’s secure storage. Windows HTTPS setup uses Git Credential Manager with repository-path isolation.

03 / CONFIDENCE

Understand access before you push.

Health checks help distinguish rejected tokens, wrong accounts, missing repository access and organization restrictions.

From download to daily use

Your first project, in four steps.

You need VS Code 1.75 or newer, Git, and a local GitHub repository. For saved HTTPS authentication on Windows, install Git Credential Manager.

  1. Install the extension

    Download the latest VSIX above. In VS Code, open Extensions → … → Install from VSIX. Choose the file, then reload VS Code.

  2. Add your GitHub accounts

    Press Ctrl + Shift + P and open GitHub: Open Control Panel Dashboard. Add a profile using browser login or a personal access token. Repeat for work, personal or client accounts.

  3. Assign the current project

    Open your repository folder, create its project-to-account mapping, then select Use for This Project. The extension applies the selected account’s Git identity and authentication setup.

  4. Check, then work normally

    Use Health to check the saved token and repository access. Continue with your usual commit and push workflow. Open different projects in separate windows when testing account isolation.

Two different identities matter.

Your commit name/email describe the author. Your credential controls whether GitHub accepts the push. This app helps configure both; branch protection and organization rules still apply.

Alternatives & competitors

The problem has solutions.
Ours connects the pieces.

Experienced developers can solve multi-account GitHub work with Git configuration, Git Credential Manager, SSH aliases and GitHub CLI. Other VS Code extensions also offer account switching. The difference is how much setup remains manual and whether account state is global or bound to the project.

NATIVE TOOLCHAIN

Git + GCM + SSH

The most flexible foundation. It can isolate commit identities and credentials by folder, username or repository path, but users maintain several settings and diagnose failures themselves.

ACCOUNT SWITCHERS

Fast active-profile changes

Git ID Switcher, GitHub Accounts Switcher and Git Account Switcher cover overlapping workflows. Some advertise stronger SSH/GPG, localization or multi-provider support.

THIS PRODUCT

Verified project context

Git Identity Manager joins an explicit repository assignment, local commit identity, supported credential routing, Health checks, companion context and approved AI reads.

Current trade-off

Version 1.6.2 is Windows-first, distributed as a VSIX, and still needs full live two-account and cross-platform verification. It should not be presented as universally safer or more complete than every alternative.

Designed around existing tools

One source of truth.
No second credential vault.

VS Code owns the profiles, mappings and secure token storage. The optional desktop companion shows those same accounts while the local VS Code window stays open.

Tokens are not returned in desktop or AI responses. Git Credential Manager receives secrets through standard input, not command arguments. The desktop uses a restricted local connection.

Know the current boundaries

Windows checks have passed locally. Full live two-account verification and macOS/Linux secure-storage and installer checks remain open. Remote SSH, WSL and web extension hosts are not connected to the desktop companion.

SSH and GitHub CLI profiles have different credential behavior. GitHub CLI switching can affect global CLI state. A saved-token Health check does not validate an SSH key.

Before you get started

A few practical answers.

Will I have to add my accounts after every restart?

Profiles and saved credentials persist. Expired or revoked tokens still need renewal. Use Save / Update Token or Reauthenticate, then apply the account to the project again.

Health passed, but my push failed. Why?

Health checks are read-only and do not bypass branch protection, organization SSO, workflow permissions or repository rules. Terminal Git may also use a different cached credential. Review the error and check the project mapping.

Can I use it without the desktop companion?

Yes. The VS Code extension is the main product. The desktop is optional and requires a running local VS Code window.

How do I update?

Download the newer VSIX, install it through VS Code’s Install from VSIX menu, and reload all project windows. Check the installed version in Extensions before testing new behavior.
